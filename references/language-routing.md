# 語言路由閘（Layer 0）

切錯語言之後，整套詞表會打在錯的字串上：中文句裡的 `harness` 被當英文套話刪掉、英文段落的 `"` 被全形化、JSON 的冒號被改成「：」。本閘只做三件事，依序：切出最小自足區塊、給每個區塊標一個母體語言、標出兩語共通的 protected span。做完才輪到後面的清單。

信心標記的意思：`grounded` 可回推到母 skill 的明文規定或實測；`inference` 是跨語言的合理外推；`speculative` 是未經驗證的設計判斷。兩個母 skill 都沒有中文語料的測量基線，所以凡是把英文側的量化結論搬到中文側的，一律從 `inference` 起跳，不得寫成實測。

## 1. 母體語言判定

### 1.1 判定單位與程序

判定單位是**最小自足區塊**：段落、列表項、表格儲存格、標題、圖說、引用塊各自獨立判，不繼承鄰居。

程序依序執行，第一個判得出結果的就停：

1. **主句謂語**。該區塊主要子句的謂語屬於哪一種語言，區塊就屬於哪一種。「這條 PR 要 rebase 一下」的謂語是「要⋯⋯一下」，ZH-matrix；`Rebase this PR before merging` 的謂語是 `rebase`，EN-matrix。（grounded：架構定義）
2. **無謂語的片語**（標題、bullet 片段、表格欄位）看中心語。「Retry 次數上限」的中心語是「上限」，ZH；`Max retry count` 全拉丁，EN。（inference）
3. **仍判不出來**就繼承所屬章節的母體語言，並在回讀時標記待確認。不要靠字元比例硬猜。技術中文的拉丁字元密度本來就高，比例門檻會系統性地把正常的中文技術段落誤判成英文段落。（speculative：沒有中文技術語料的比例分布資料，任何門檻值都是猜的，所以本檔不給門檻值。）

助詞、語序、量詞都算中文謂語結構的一部分。一個句子只要靠中文語序把英文動詞接起來（「先 review 一輪再 merge」），就是 ZH-matrix，不因為實詞是英文而翻面。（inference）

### 1.2 硬規則：詞表不得越界

**ZH-matrix 區塊內的英文名詞片語、識別符號、術語、引號內的英文，一律是術語或 protected span，永遠不是英文 ban list 的候選。**（grounded：`protected-spans.md` 1.2／1.4，以及母 skill「中英混排句中的英文詞按當前句子的實際語義判斷，不機械套英文詞表」）

- 「這次 release 主要是把 `delve` 從 prompt 模板裡拿掉」。`delve` 是被提及的字串，不是文風命中。
- 「這層 abstraction 的耦合比想像中深」。`abstraction` 不歸英文 ban list 判，歸第 5 節判它有沒有已定的中文說法。

**反向同樣成立。EN-matrix 區塊內的中文詞不套臺灣用語替換，也不做全形化。**（inference：`protected-spans.md` 1.3 只寫了引號內原文，這裡外推到所有嵌入的中文專名。）

- `The 說人話 skill ships with a Taiwan usage layer.` 中間那三個字是專名，原樣。

升格只有一種情形。EN-matrix 段落裡若有一整句以中文謂語自足的子句（多半在引號裡），那句本身成為 ZH span，照樣跑 Layer 1；嵌入的名詞、標題、專名不升格。（inference）

### 1.3 常見誤判

| 誤判 | 症狀 | 正解 |
|---|---|---|
| 英文 ban list 掃進 ZH 區塊 | `landscape`／`harness`／`delve` 在中文句裡被刪 | 要嘛是專名（`lm-eval-harness`），要嘛歸第 5 節 |
| 臺灣用語表掃進 EN 區塊 | 英文句裡的中文引文被改字 | 引文原樣（grounded：`protected-spans.md` 1.3） |
| 全形化掃進 protected span | JSON 的 `:` 變成「：」、路徑的 `.` 變成「。」 | 見 3.4 |
| 中文密度規則掃進 EN 區塊 | 一個 em-dash 就被改掉 | 見 3.3 |

## 2. 分區換母體語言的文件

雙語 README、雙語公告、雙語 release note 這類文件，母體語言按章節切，不按檔案切。

- 語言切換點本身是 protected span。`## English`、`## 中文`、`<details>` 的 summary、並排欄位的欄頭，都不改、不合併、不翻譯。（inference）
- 每個區塊**各自**計密度：中文區塊算字元，英文區塊算詞，不把兩側加總平均。加總會讓較短的一側被較長的一側稀釋，Tier 判斷整個失準。（inference）
- 不在中文區塊插英文摘要，也不在英文區塊補中文註解。那是新增內容，不是改寫。（grounded：保真合約）
- 中文區塊裡出現英文結構的影子（「不僅⋯⋯而且⋯⋯」連發、「透過⋯⋯來⋯⋯」堆疊）仍然是 ZH span，用中文結構表判，不用英文結構模板判。（inference）

**回讀檢查**：從頭數一次區塊，每個區塊只有一個母體語言標籤，沒有任何區塊被兩套清單各改過一次。

## 3. 交界標點

### 3.1 CJK／拉丁交界的空格

中文與英文、數字、行內程式碼之間留**一個半形空格**。（grounded：`punctuation.md` 1）

不加空格的四種情形：

1. 緊鄰全形標點（「用 Dorico 記譜，」不是「記譜 ，」；「對位法（counterpoint）」不是「（ counterpoint ）」）。
2. protected span 內部。
3. 區塊的頭尾。
4. 邊界已經是換行或列表符號。

protected span 的**外緣**照樣加空格：「執行 `bin/migrate --tenant=prod` 之後」，外面加，裡面一個字元都不動。

### 3.2 引號

- ZH-matrix 的對話與提及一律「」，層內『』，**即使被引的話是英文**：他說「ship it, we'll fix forward」。不要因為引文是英文就換回 `""`。（grounded：`punctuation.md` 1／3 定形制；「即使引文是英文」這一步是 inference）
- EN-matrix 段落保留 `""` 與 `''`，不全形化，不換成「」。（inference）
- 刪節號在 ZH span 用 ⋯⋯，不用 `...`；英文段落的 `...` 不動。（grounded＋inference）

### 3.3 破折號與分號

**sepia 的白名單「單一 em-dash 或分號不算 AI 味」只管 EN-matrix span。**（grounded：該白名單出自英文側的觀察，母 skill 沒有任何中文對應資料。）

- **EN span**：一個 em-dash、一個分號、一個 `delve` 都不算命中，只有成群才算。不要為了「看起來不像 AI」去動英文段落裡唯一的那個分號，過度矯正本身就是指紋。
- **ZH span**：破折號是全形 ——，密度規則照原樣執行，不因為英文側寬鬆就放寬。計數單位是插入處不是符號：一對「——插入——」計一處，單個 —— 承擔轉折或補充也計一處。首句破折號起手、單段兩處以上、連續多段都靠破折號承接，任一命中就降密度。（grounded：`structures.md` 20）
- 分號連用在 ZH span 是破折號腔的伴隨訊號，與英文白名單無關。（grounded：同上條明列「常伴隨分號連用」）
- **保留條件**：標題與命名裡的連接符、引用原文、破折號本身是討論物件、全段僅一處且確實承擔插入語氣。（grounded：`structures.md` 20）
- 降密度時改成的冒號要站得住，只有列舉、引文、定義三種用法合法，否則改逗號或直接斷句。（grounded：`punctuation.md` 2）

### 3.4 兩語共通的保護區

行內程式碼、命令、版本字串、錯誤訊息、路徑、識別符號、環境變數、JSON／YAML 片段，在兩種母體語言下受同一組保護：

- 內部標點**不全形化**。`{"retry": 3}` 的冒號、`v1.7.0` 的點、`C:\Users\USER` 的反斜線都照原樣。（grounded：`punctuation.md` 範圍例外＋`protected-spans.md` 1.4）
- 內部**不插空格**。`--tenant=prod` 不寫成 `--tenant = prod`。（grounded：同上）
- 密度計數時**各算一個單位**。`bin/migrate --tenant=prod` 是一個單位，不是三個字也不是四個詞。（inference：兩個母 skill 都沒定義技術字串的計數方式，統一成一個單位是為了讓中英兩側的 Tier 判斷可以互相比較。）

**回讀檢查**：搜「：」「，」「（」看有沒有落進 code span；搜 code span 內部有沒有被插入空格；搜 `...` 確認不是把英文省略號誤改成 ⋯⋯。

## 4. 平行雙語文件

**不得由一側翻譯另一側。兩側都從同一份事實清單各自寫成。**（inference：翻譯必然把來源語的句法帶進目標語，`translation.md` 整份都在處理這件事；讓兩側各自從事實出發是繞開它最直接的做法，但沒有測量支持。）

事實清單至少要列：

- 版本字串與日期
- 數量、指標、比較基線
- issue／PR／RFC 編號
- 破壞性變更
- 遷移步驟與順序
- 承諾（時程、支援範圍、後續動作）
- 能力邊界（明講不支援什麼、什麼還沒做）

改完之後把兩側的事實集合逐項核對。**只出現在一側的事實是錯誤，不是風格差異。**（grounded：保真合約直接推得。）修法只有兩種，補到缺的那一側，或連同另一側一起刪；刪事實由使用者決定，不自行處置。

允許不同的是結構、長度、順序、語域。中文側比英文側短是正常的，計數單位本來就不同；英文用祈使句 bullet、中文用完整句，兩邊都合法。**不要為了讓兩欄等長而硬湊長度或砍句。**

**回讀檢查**：兩側各跑一次事實清單點名，每一項都能在兩側指出出處。

## 5. 表演性中英夾雜

母 skill 對句中英文術語是整批豁免，這個豁免太寬，它把 `p99` 和「這件事我先 own 起來」放進同一類。改成兩條明列的清單。

**保留（KEEP）**：識別符號、API 名、命令、產品名、指標（`p99`、`QPS`、`latency`）、沒有定譯的既定術語。

**替換（REPLACE）**：已有臺灣說法、英文只多帶語域不多帶語義的：

| 夾雜 | 改 |
|---|---|
| align／sync | 同步 |
| push | 推進 |
| own | 負責 |
| block | 卡住 |
| review | 審查／看過 |
| follow up | 追蹤 |
| deadline | 期限 |
| highlight | 重點 |
| cover | 涵蓋 |

**判準**：這個詞有沒有已定的臺灣說法？換成中文之後句子有沒有掉資訊？前者有、後者沒有，就換。（grounded：母 skill 要求按當前句子的實際語義判斷；縮成這兩題是 inference。）

**訊號與預設動作**：一段裡有兩個以上可替換的夾雜，就是語域訊號，兩個都換；只有一個，放行。（speculative：門檻取二是設計選擇，沒有中文語料支持；取二是為了跟破折號密度規則同一種形狀，單次不算，成群才算。）

**不適用**：引號內的話、引用的聊天記錄、程式碼與其註解裡的原文。人家原話怎麼講就怎麼留。（grounded：`protected-spans.md` 1.3／1.4）

**同形異義**：同一個字在不同句子身分不同，看它指的是不是介面上的具名物件。

- 「這個 PR 的 Review 還沒過」指的是 GitHub 上那個具名狀態，保留。
- 「我先 review 一下」只是「看過」，換。
- 「p99 latency 從 800ms 降到 120ms」帶了度量，保留。
- 「這幾天延遲很高」沒有度量，中文說法一樣成立，兩種寫法都放行，不強制替換。

**回讀檢查**：每段數一次可替換夾雜的殘留數，應為 0 或 1。換過的地方回頭確認語義沒漂。`own` 改成「負責」之後，責任主體有沒有跟著換人？（grounded：`protected-spans.md` 1.2）
