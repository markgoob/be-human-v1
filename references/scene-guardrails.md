# 場景禁改表

> 本檔案是解釋、示例與操作細則；行為合同的單源是 `SKILL.md`，兩處表述不一致時以 `SKILL.md` 為準。

先判場景，再判斷哪些內容不能亂動。去模板感不等於把所有文字都改成一個口氣。

只要環境裡能讀 `references/`，預設先用 [Protected Spans](./protected-spans.md) 劃出不能漂的片段，再按這裡的場景禁改項收窄改寫範圍。

本檔案只定義大場景邊界。README、release note、forum post、issue reply 這類更細的發布場景，即使初判像 `docs` 或 `status`，也要補看 [Scene Packs](./packs/_scene-packs-zh.md)，同時保留這裡更保守的事實和術語邊界。

## `chat`

目標：

- 自然、直接、有回應感

預設檔位：

- `minimal`

無源引用預設策略：

- `rewrite-safe`

不要亂動：

- 不要為了「去 AI 味」把回覆改得更硬
- 不要憑空拔高語氣或補價值判斷
- 不要把簡單回應改成總結陳詞
- 不要替對方做心理分析、關係診斷或空泛安撫

優先保留：

- 對話節奏
- 具體回應關係
- 合理的口語停頓
- 使用者明確要求保留的原話或引用片段

## `status`

目標：

- 事實密度高，讀完知道進展、問題、下一步

預設檔位：

- `minimal` 或 `standard`

無源引用預設策略：

- `audit-only`

不要亂動：

- 不要刪時間線
- 不要刪責任歸屬
- 不要把風險說輕
- 不要為了「更像人」犧牲彙報效率

優先保留：

- 時間、動作、結果、風險、阻塞點
- 數字、日期、範圍和責任歸屬

## `docs`

目標：

- 可檢索、可復現、可引用

預設檔位：

- `minimal`

無源引用預設策略：

- `audit-only`

不要亂動：

- 不要破壞術語穩定性
- 不要改掉檢索詞、命令、介面名、欄位名
- 不要為了口語化犧牲系統主語和命令式說明
- 不要把正式說明改成閒聊體

優先保留：

- 術語
- 系統行為主語
- 步驟順序
- 限定條件
- 命令、路徑、引數、欄位、報錯和狀態碼

## `public-writing`

目標：

- 語域統一，有判斷但不端著

預設檔位：

- `standard`

無源引用預設策略：

- `rewrite-safe`

不要亂動：

- 不要為了節奏製造誇張判斷
- 不要把剋制文風改成自媒體吆喝腔
- 不要硬造金句
- 不要把正式公告改成社媒評論

優先保留：

- 作者原有立場
- 正常的正式度
- 必要的修辭節奏
- 已有事實、歸屬和可核對引用

長文補充：

- 中文長文（約 1000 字以上）預設優先 `bounded` scope，尤其是觀點文、檢討文、評論文和帶段落節奏的公開文字：句內洗實句、整句空話進「建議刪除（待確認）」清單交使用者拍板，不併句不重排
- 使用者明確要求「完全原樣 / 一句都別刪 / 嚴格保句數」，或反饋 `bounded` 仍刪多了時，再切到更嚴格的 `in-place`（整句空話也不刪，只句內降調）
- 使用者 prompt 含 `保長度 / 別縮水 / 字數 / 節奏 / 別刪 / 儘量原樣` 這類訊號時，即使原文沒到 1000 字，也按長文處理
- `bounded / in-place` 下都不把整段壓成短摘要；先保段落節奏和承擔轉場的重複，區別只在整句空話是「進刪除清單」還是「留著只做句內降調」
- 標點腔（[結構反模式](./structures.md) 第 20 條）是**句內動作**：破折號按語義改回冒號、逗號或斷句，**不進「建議刪除（待確認）」清單**；同段的整句空話仍照常進清單。兩類動作分開走，不因為同一段裡都有就混成一種處理

## `fiction`

目標：

- 保住作者的敘事聲音、視角與世界，只清敘述層的機器腔

預設檔位：

- `minimal` 或 `standard`

無源引用預設策略：

- 不適用。虛構世界內的引用、書名、報導、檔案、碑文都是設定的一部分，不進無源引用流程；只有作者在正文之外（作者註、後記、譯註）引現實資料時，才回到 `audit-only`

不要亂動：

- 對白與世界內文件是刻畫，不是病灶：角色說的話、日記、簡訊、公告、書信裡出現套話、支語、破碎文法、禁用詞，都照留。要清的是敘述層
- 作者刻意的重複、韻律、斷句與留白不是節奏問題，不要拉平
- 意象與感官細節不套用「無源裝飾細節」的刪除規則（那條只管非虛構）
- 借景抒情不是機器腔，只有連續兩場以上機械對應才處理，而且是「疏，不是刪」
- 不得因為「讀起來像 AI」就把作者的語域拉向中性
- 結構性插入（加事件、加副線、加關係）只在 `write` / `recreate` 合法，`refactor` / `review` 一律只回報，不落筆

優先保留：

- 敘事聲音、人稱與視角
- 對白的語域差異、角色口音和口頭禪
- 段落節奏、留白和承擔功能的重複
- 意象系統與感官細節
- 世界內既有的專有名詞、設定、時間線和因果鏈

配套讀法：

- 這一節只定場景禁改底線；中文虛構的字面層（詞彙、句式、標點、四字格、翻譯腔）看 [zh-fiction-surface](./fiction/zh-fiction-surface.md)
- 敘事層（場景、視角、資訊釋放、因果與情節）看 [narrative-pass](./fiction/narrative-pass.md)

## 混合場景處理

如果一段文字同時命中多個場景：

1. 先判主要用途
2. 先劃 protected spans，再以主場景的禁改項為上限
3. 只清理次場景裡明顯突兀的詞，不追求絕對純化
