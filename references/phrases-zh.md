# 中文禁用短語表

> 本檔案是解釋、示例與操作細則；行為合同的單源是 `SKILL.md`，兩處表述不一致時以 `SKILL.md` 為準。

> 來源：awesome-ai-research-writing、日常 AI 輸出觀察、公眾號/小紅書 AI 味總結、Linux.do / X / 即刻社群反饋。

本表預設列代表項，不追求把同義變體全部窮舉出來。遇到沒收錄的新說法，先看它是不是現有模式的同類變體；只有現有模式吃不住，或誤殺邊界變了，才值得補成新詞條。

**這份清單是舉例，不是邊界。** 這裡管的是修辭動作，不是字面：把一個命中的說法換一套字繼續做同一件事——同樣的姿態、同樣的抬價、同樣的空承諾、同樣的替對方下結論——仍然算命中。判斷一個新說法要不要處理，看它在做什麼動作，不看它有沒有出現在下面的列表裡。反過來也成立：出現在列表裡但在當前句子裡承擔實義的詞，按誤殺防護放行。

## Tier 1：預設替換

這些詞/短語在 AI 文字中出現頻率遠高於人類文字。預設替換，但在誤殺防護場景中允許保留（見 `severity.md`）。

### 工程師腔 / 除錯腔（AI 模仿程式設計師說話）

AI 在程式設計輔助場景中模仿 SRE/工程師口吻，把 debug 術語用到日常對話裡，像在寫 postmortem：

同類姿態詞預設一併處理，不要求逐詞收錄。遇到近義變體，先併到這一類。

- 穩穩兜住 → 處理好、搞定
- 砍一刀 → 刪掉、去掉
- 收口 → 收尾、結束
- 收窄 → 縮小範圍
- 打掉問題 → 修好、解決
- 避免漂移 → 別跑偏
- 根因 → 原因、根本原因
- 有點滿 → 內容太多了
- 更穩 / 最穩 / 不穩 → 更可靠 / 最可靠 / 不可靠；如果上下文已有指標、技術物件或穩定性結果，不要機械改
- 做快、做穩 / 又快又穩 / 更快更穩（用於產品自誇、專案介紹、營銷式 README）→ 改成具體物件、具體動作或直接刪掉；如果上下文已有真實主體、指標或穩定性結果（錯誤率、延遲、可用性、上線觀察等），不要機械改
- 穩穩接住（用於人/情緒/所有人/需求）→ 刪掉承接姿態，改成具體回應或具體處理
- 夾具（fixture）→ 固定方案、測試資料（說清楚具體指什麼）
- 接住（用於你/大家/情緒/脆弱/需求等抽象賓語）→ 回應、處理；如果賓語是 `流量 / 請求 / 峰值 / 異常` 且有系統主語和結果，先不要機械改
- 拆開看 → 分開說、逐個看
- 偏硬 → 太死板
- 落盤（用於抽象動作 / 空物件 / 泛化表演時）→ 儲存、寫入、記下來；如果賓語是 `程式碼 / 部署 / 配置 / 文件 / 設計方案` 等具體技術物件，且能複述"寫到哪裡、做了什麼"，先不要機械改
- 已經落下去（不帶具體技術物件時）→ 已經做了、已經生效；如果上下文已經說清"落到哪個檔案 / 哪一版 / 哪個分支"，可以保留
- 對上了 → 吻合、一致
- 坐實了 → 確認了、證實了
- 做一個更硬的排除法 → 用排除法再查一遍
- 把差異收窄了 → 縮小了差異
- 抓到的現象 → 發現的問題
- 兜底 → 保底處理、兜住邊界情況
- 壓實 → 落實、確認好
- 收斂 → 縮小範圍、逐步收攏
- 收束 → 收尾、結束
- 鎖住 → 固定好、確認
- 更硬 / 硬寫 → 更死板 / 直接寫死（說清楚為什麼）
- 口徑 → 說法、措辭
- 這輪 → 這次
- 能吃 → 能接受、能處理
- 說穿 → 說白了（刪掉，直接說）
- 不躲 / 不藏 / 不繞 / 不逃 → 刪掉，直接說就行
- 說人話就是 → 刪掉，直接說

### 庸醫問診腔（AI 模仿診斷專家口吻）

AI 把排查過程戲劇化，模仿醫生找病因的語氣：

同類「找出來」式變體優先按這一類處理，例如 `扒開`、`拽出來`、`撈出來`。

- 摳出來 / 揪出來 → 找出來、定位
- 我不猜 / 不靠猜 / 不瞎猜 → 刪掉，說清楚你掌握了什麼資訊

### 暴力動作腔（AI 用激烈動詞表達普通操作）

AI 用"暴力"動詞凸顯執行力，實為多餘的氣勢渲染：

同類暴力動詞優先併到這一類，不要求每個新變體單獨入庫。

- 補一刀 → 再加一點、補充
- 更狠 / 狠一點 → 更徹底、更嚴格
- 狠狠幹 → 刪掉（AI 硬凹幹勁）
- 打壞 → 破壞、損壞
- 拍腦門 → 隨便決定（說清楚是誰在隨便決定）
- 拍板 → 決定、定了（說清楚誰定的）
- 切 / 傷（作為動作隱喻）→ 改、刪、調整

- 硬核（乾貨/分析）→ 刪掉

- 梳理 → 整理
- 盤點 → 列舉、介紹
- 避坑 / 踩坑 / 不踩坑 → 注意、別犯的錯

- 萬字長文 → 刪掉
- 建議收藏 → 刪掉
- 強烈推薦 → 刪掉或說清楚為什麼推薦
- 劃重點 → 刪掉
- 絕絕子 → 刪掉（AI 硬凹網感）
- 誰懂啊 → 刪掉
- 真的會謝 → 刪掉
- 姐妹們 → 刪掉（AI 硬凹人設）

### 洞見感 / 價值拔高骨架
- 真正的 X 不是……而是…… → 多數直接說真正成立的判斷
- 這不僅僅是……更是…… → 多數刪掉拔高層，保留事實判斷
- 最後比拼的是…… → 直接說真正決定因素是什麼

### 過渡廢話
- 綜上所述 → 刪掉或直接給結論
- 總而言之 → 同上
- 總的來說 → 同上
- 總體來看 → 同上
- 由此可見 → 刪掉
- 換句話說 → 刪掉（說一遍就夠了）
- 簡而言之 → 刪掉
- 歸根結底 → 刪掉
- 不言而喻 → 刪掉
- 可以說 → 刪掉（直接說就行）
- 某種程度上 → 刪掉或說清楚什麼程度
- 從某種意義上說 → 同上
- 在此過程中 → 刪掉
- 在這個過程中 → 刪掉
- 本質上 → 刪掉或說清楚
- 核心在於 → 直接說
- 關鍵在於 → 直接說
- 由此可以看出 → 刪掉

### 正能量收尾模板
- 與其……不如積極擁抱…… → 刪掉，不做雞湯
- 只有……才能…… → 看上下文，AI 喜歡用這個做總結
- 讓我們拭目以待 → 刪掉
- 未來可期 → 刪掉

### 無源引用（公開寫作中尤其像 AI）
- 研究表明…… → 給出具體研究名稱或刪掉
- 資料顯示…… → 給出具體資料來源或直接給資料
- 有專家指出…… → 說清楚哪個專家
- 業內人士認為…… → 說清楚誰
- 據報道…… → 給出具體媒體和時間

### 諂媚/元評論
- 好問題！→ 刪掉
- 你說得很對 → 刪掉
- 這是一個很好的觀點 → 刪掉
- 讓我來為你解釋 → 刪掉
- 希望這對你有幫助 → 刪掉
- 如果你有其他問題 → 刪掉
- 好，/ 行，（作為回覆開場）→ 刪掉，直接響應
- 一句話總結 → 刪掉，直接給結論
- 結論先說清楚 → 刪掉，直接給結論
- 簡單的說 → 刪掉
- 不是……而是…… → 看是否必要，多數可刪掉前半句
- 我先……再…… → 刪掉，直接說要做什麼

同類「先宣佈自己要開始總結/翻譯」的提示句，預設也按這一類處理。

### AI 主動出擊腔（血壓升高類）

AI 過度表達執行意願，把確認環節變成推銷話術：

- 我已確認 → 刪掉（無需宣告）
- 我立馬開始 → 刪掉，直接做
- 要不要我…… → 刪掉，等使用者提需求
- 如果你願意…… → 刪掉
- 如果你要…… → 刪掉
- 只要你回覆我…… → 刪掉
- 你一回復我就…… → 刪掉
- 你就確認一點 → 刪掉
- 順手 → 刪掉（暗示舉手之勞來推銷額外操作）
- 我先…… → 刪掉，直接做

### 過度接住 / 心理判斷腔

AI 喜歡把普通回應寫成「諮詢式安撫」，一邊過度接住，一邊替對方下心理結論：

- 我就在這裡 → 多數刪掉，直接回應
- 不躲 / 不藏 / 不繞 / 不逃 → 刪掉，別演姿態
- 穩穩地接住你 / 所有人 / 這份脆弱 → 刪掉承接姿態，改回具體回應
- 你只是太久沒被穩穩接住了 → 刪掉，別替對方做心理判斷
- 不用向我解釋 → 刪掉，除非上下文確實在安撫對方
- 你不是敏感 / 不是想太多 / 不是矯情 → 看是否有明確依據；多數不要替對方下結論
- 你太清醒了 / 太懂了 / 太對了 → 刪掉誇獎層，直接回應內容
- 這次我懂了，我真的懂了 → 刪掉，別演「終於完全理解你」

同一個「接住」字，優先看賓語：

- 賓語是 `你 / 你們 / 所有人 / 情緒 / 脆弱 / 委屈 / 需求`，預設按這一類處理
- 賓語是 `流量 / 請求 / 峰值 / 異常`，先回到技術語境判斷，不要因為字面命中就硬改

### 鄭重預告 / 身份認證式誇獎

AI 喜歡先預告「我要說句大的」，再順手給對方發身份認證：

- 我必須很認真地說一句 → 刪掉，直接說
- 我要講一個更深一點的東西 → 刪掉，直接說
- 你問到了問題的核心 → 刪掉，直接回答
- 你的觀察力太敏銳了 / 這個思路簡直絕了 → 刪掉誇獎層，保留具體判斷
- 絕對是頂刊作者的素養 / 頂級研究者才具備的批判性思維 → 刪掉身份認證式誇獎，改成對內容的具體評價

### 抒情詞給抽象概念穿衣服

單個出現完全正常；同段 2+ 個、且描寫物件是記憶、成長、時代、答案等抽象概念時標記。處理的是密度和搭配物件，不是這些詞本身。

- 安放 / 抵達 / 微光 / 褶皺 / 豐盈 / 滾燙 / 輕盈
- 赤裸 / 剝開 / 鋒利 / 堅硬 / 柔軟

寫具體事物時放行：`把藥盒安放在床頭`、`剝開一隻橘子`、`刀口很鋒利` 都是實義。小說、詩歌、散文、歌詞等文學場景整體放行；使用者明確要求抒情語體時也放行。命中時把抽象概念改回直接陳述，不要換一組抒情詞繼續包裝。

## 翻譯腔（中文特有 AI 味）

這些是英文思維直譯到中文的痕跡：

- "一個……的……的……" 長定語結構 → 拆成短句
- 被動語態堆砌（"被最佳化""被改進""被賦予"）→ 用主動句
- "基於……" 開頭 → 看能否直接說
- "透過……來……" → 看能否簡化
- "對於……而言" → 看能否刪掉
- "在……方面" → 看能否刪掉
- "從……的角度來看" → 看能否簡化
