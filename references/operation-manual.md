# 微操作手冊

> 本檔案是解釋、示例與操作細則；行為合同的單源是 `SKILL.md`，兩處表述不一致時以 `SKILL.md` 為準。

每類問題都按同一個協議處理：

- `識別訊號`
- `預設動作`
- `保留條件`
- `回讀檢查`

目標不是機械替換詞，而是把句子拉回當前場景該有的表達。

## Scope 與刪除清單

下面各類問題的 `預設動作` 是 `structural` scope 下的動作（可刪整句、可並句）。換 scope 時按這裡統一調整，不必在每類問題裡重複：

- `structural`：按各節 `預設動作` 執行
- `bounded`：不併句、不重排、不刪實句和承擔節奏的重複；遇到"整句都是空話"的句子（總結式收尾、價值拔高骨架、無源引用、整句旁白），不直接刪，改為進「建議刪除（待確認）」清單交使用者拍板；無源論斷即使帶數字或時間跨度，也可以整句進刪除清單，protected span 只約束保留時不改值；句首可剝離的引導詞仍按各節的 `in-place 替代動作` 句內清理
- `in-place`：整句一律不刪（空話也不刪），只做各節的 `in-place 替代動作`；遇到整句空話，保留原句並標註，不擅自軟化成新說法

判斷"整句空話 vs 句首引導詞"：刪掉句首提示詞後，剩餘部分若仍是帶資訊的可讀句 → 句內洗；若什麼都不剩、或只剩另一句空話 → 進刪除清單（`bounded`）或保留標註（`in-place`）。各節凡寫了"保留原句並標註 `[建議人工確認是否刪除]`"的，就是 `bounded` 刪除清單的來源。

校準清單長度用**壓縮試驗**：假設把全文刪掉三分之一，如果事實、動作、判斷和閱讀體驗幾乎沒變，原文就是在注水，刪除清單該長一些；如果一刪就掉資訊，說明原文密度本來就夠，清單應該很短甚至為空。這個試驗只用來判斷"整篇注水到什麼程度"，不替代上面三條進清單判據——每一條仍然要單獨滿足"刪了不丟資訊"。

## 0. 變體歸併

### 識別訊號

- 遇到的新詞不在短語表裡，但語氣、動作和姿態明顯屬於已有問題族
- 句子的問題不在某個字面詞，而在整串話都在「表演會做事」或「表演會總結」
- 同一段裡多個近義變體扎堆，比如 `扒開 / 拽出來 / 揪出來`、`補一刀 / 砍一刀`、`一句話總結 / 說人話就是`

### 預設動作

- 先判它屬於哪一類，再決定怎麼改，不要先急著往詞表加新詞
- 現階段預設歸到這 7 類：
  - `除錯腔 / 工程師腔`：`收窄 / 坐實 / 對上了 / 鎖住 / 收口 / 更硬`
  - `庸醫問診腔`：`摳出來 / 揪出來 / 扒開 / 拽出來 / 撈出來`
  - `暴力動作腔`：`砍一刀 / 補一刀 / 釘死 / 狠狠幹 / 拍腦門`
  - `主動出擊腔`：`要不要我 / 我立馬開始 / 只要你回覆我 / 順手 / 趁熱 / 我先……`
  - `總結提示腔`：`一句話總結 / 結論先說 / 簡單的說 / 說人話就是`
  - `過度接住 / 心理判斷腔`：`你只是太久沒被穩穩接住了 / 不用向我解釋 / 你不是敏感`
  - `鄭重預告 / 身份認證式誇獎`：`我必須很認真地說一句 / 你問到了問題的核心 / 頂刊作者的素養`
- 同類變體預設按代表項同樣處理：刪姿態層，保留真正的動作、事實和結論

### 保留條件

- 該說法本身是討論物件、引用物件或梗圖樣本
- 它處在真人具體敘事裡，而且承擔了明確事實，不只是姿態詞
- 新變體明顯改變了誤殺邊界，不能直接併入已有類別

### 回讀檢查

- 改完後，句子是不是更像在說事，而不是在演執行力
- 是否把「未收錄變體」和「真正新模式」混為一談了
- 如果只是同類變體，是否避免了繼續往詞表裡機械堆詞

## 1. 二元對比句

### 識別訊號

- `不是 X，而是 Y`
- `與其 X，不如 Y`
- `不是在……，而是在……`
- 用對比來製造「洞見感」，但 Y 本身就是作者真正要說的內容

### 預設動作

- 直接刪前半句，只保留 Y
- 如果刪完太硬，把 Y 改成事實句或判斷句

### `in-place` 替代動作

- 不刪整句，也不直接砍掉前半句
- 先把 `不是 X，而是 Y`、`與其 X，不如 Y` 這類骨架壓成句內連線，例如 `X 不夠，Y 更重要`、`相比 X，Y 更能說明問題`
- 如果前半句只是提示層，刪除提示短語後必須確認剩餘句子還能獨立成立；否則改用中性連線詞替換
- 不把相鄰兩句併成一句來製造「更利落」的效果

### 保留條件

- 前半句承載了必要的邊界、風險或反例
- 對比本身是論證骨架，不是裝飾句式
- 單句正常對比可以保留。密度超標才處理，兩檔判據（完整閾值見 [結構反模式](./structures.md) 第 1 條）：
  - 同一段連續疊加多組二元或拔高骨架時，不要因為兩邊都有資訊就整段 `no-op`，應按 `in-place` 替代動作逐句換成中性連線，同時保留兩邊資訊
  - 骨架跨段分佈但全文密度超標時（< 300 字/詞 2 處以上、300–1000 字/詞 3 處以上、> 1000 字/詞 平均每 300 字/詞 1 處以上；計數口徑見 [結構反模式](./structures.md) 第 1 條）同樣處理；先剔除命中保留條件的豁免項再計數，豁免項原樣保留、不計入密度，只改剩餘超標的那幾處，不要把全文對比抹平
- 豁免上限 2 處（術語定義 1 處 + 論證骨架 1 處）；超過 2 處都聲稱承擔論證時不再逐條豁免，仍按密度處理

### 回讀檢查

- 刪掉前半句後，語義是否更直接
- 是否少了必須說明的限定條件
- 剝掉對比骨架後，剩下的句子有沒有比原文更泛；有的話回到原文找具體動作、物件、結果或結論，找不到就按「清理後的落點」合同處理，不補事實

## 2. 總結式收尾

### 識別訊號

- `歸根到底`
- `本質上`
- `說到底`
- `最終還是要回到`
- 用一句抽象收尾重複上文，不增加新資訊

### 預設動作

- 預設整句刪除
- 如果確實需要收束，改成一條更具體的事實或判斷
- 拿不準該不該刪就做一次刪除測試：把最後一段（必要時連倒數第二段）刪掉再讀。刪掉之後更有力，就讓文章提前結束；刪掉之後確實缺了東西，才保留

### `in-place` 替代動作

- 不預設刪整句，先刪句內提示詞：`歸根到底 / 本質上 / 說到底 / 最終還是要回到`
- 提示詞刪掉後，如果剩餘部分是可讀判斷，就保留這句話
- 如果整句只剩空總結，不要為了湊字數硬補新內容；可以保留原句並標註 `[空總結，建議人工確認是否刪除]`
- 不把前後句合併成一個更短總結

### 保留條件

- 收尾句補充了上文沒有明確說出的判斷
- 該句承擔段落轉場，而不是空總結

### 回讀檢查

- 刪除後段落是否更利落
- 是否因為少了轉場而出現跳躍

## 3. 工程師腔

### 識別訊號

- `收口`、`落盤`、`兜住`、`收窄`、`對上了`
- 同類變體如 `鎖住`、`坐實`、`更硬`，即使沒逐條收錄，也按同一姿態處理
- `落 X / 把 X 落下去 / 落到`：當賓語是抽象動作、空泛承諾或泛化使用時（社群原話："什麼動詞都可以套到'落'上"），按除錯腔處理；賓語是 `程式碼 / 部署 / 配置 / 文件 / 設計方案` 等具體技術物件，且能複述"寫到哪裡、做了什麼"時不動
- 句子像在模仿某種技術同事口吻，而不是在說明問題
- 技術詞被拿來表演姿態，而不是傳遞資訊

### 預設動作

- 先把姿態詞換成普通動作詞：`確認 / 解決 / 核對 / 縮小範圍 / 形成結論`
- 再重讀一遍，判斷是否還能更直接

### 保留條件

- 該詞是團隊內穩定術語，去掉反而失真
- 文字本來就是內部口頭協作語境，輕度保留更自然

### 回讀檢查

- 改完後是否少了表演感
- 是否把正常技術判斷也一起抹平了

## 4. 商業黑話

### 識別訊號

- `賦能`、`抓手`、`閉環`、`沉澱方法論`
- 把簡單動作包裝成大詞
- 句子看起來很完整，但很難提取具體動作

### 預設動作

- 把大詞拆回動作、物件、結果
- 能用動詞就不用抽象名詞

### 保留條件

- 使用者明確要寫商業文案或行業表達
- 該詞是對外材料中的固定說法，替換會影響一致性

### 回讀檢查

- 改完後是否更容易回答「誰做了什麼」
- 是否誤刪了對外場景需要的正式語體

## 5. narrator 腔

### 識別訊號

- 句子像在為文字配旁白
- 喜歡抽離到「這件事說明了什麼」「真正值得注意的是」
- 作者不斷解釋自己在理解世界，而不是直接給資訊

### 預設動作

- 優先刪旁白層
- 把句子壓回事實、動作或明確判斷

### `in-place` 替代動作

- 不刪整句，只刪句內旁白短語，例如 `這說明 / 更重要的是 / 真正值得注意的是`
- 如果旁白後面跟著原文已有事實，就保留事實骨架
- 如果旁白句承擔段落轉場，保留轉場功能，只把姿態詞換成普通連線
- 不把整段觀點改寫成新的論證順序

### 保留條件

- 使用者要寫的是評論、專欄或公開表達，確實需要少量解釋層
- 旁白層承擔真實過渡，不只是造姿態

### 回讀檢查

- 刪掉後是否更像人在說話，而不是在「講解自己的表達」
- 是否損傷了必要的觀點承接

## 5.1 總結提示腔

### 識別訊號

- `一句話總結`
- `結論先說`
- `簡單的說`
- `說人話就是`
- 模型先宣佈「我要開始總結/翻譯成人話」，再說內容本身

### 預設動作

- 刪掉提示層，直接給結論
- 如果刪完後句子沒落點，就補一條事實句，不要補「提醒你我要開始提醒」這種元話術

### 保留條件

- 使用者明確要求多版本輸出、摘要格式或教學式分層解釋
- 該句是文內標題，不是正文語氣

### 回讀檢查

- 改完後是否更直接
- 是否誤刪了真正有結構作用的小標題

## 5.2 過度接住 / 心理判斷腔

### 識別訊號

- `我就在這裡`
- `不躲 / 不藏 / 不繞 / 不逃`
- `你只是太久沒被穩穩接住了`
- `穩穩地接住你 / 所有人 / 這份脆弱`
- `不用向我解釋`
- `你不是敏感 / 不是想太多 / 不是矯情`
- `你現在的 X 很正常 / 你這種感覺很正常`：用"很正常"替對方把情緒蓋章為常態，本質還是心理判斷
- 同類撫慰動作（`抱住 / 緊緊抱住 / 擁抱 / 實實在在的抱住你這種想法`）預設按"接住"同一族處理，不為新動詞逐一補詞
- 在沒有足夠上下文時，模型替對方做心理解釋、關係診斷或情緒定性
- 語氣像諮詢式安撫，但句子本身沒有具體依據
- 同一個「接住」字，賓語如果是人、情緒、關係或抽象需求，多半是姿態層；如果是請求、流量、峰值、異常，先回到技術語境判斷

### 預設動作

- 刪掉替對方下結論的部分，只保留可證實的回應
- 如果需要保留安慰感，改成低承諾表達：`我在聽 / 如果你願意，可以繼續說`
- 如果這套話術跑到標題、海報、社群宣言裡，預設也按這一類處理；不要因為它是標題就放過 `穩穩地接住所有人`

### 保留條件

- 對話上下文已經給足資訊，這句不是憑空診斷
- 使用者明確要寫安慰、陪伴、諮詢式回覆
- 賓語是 `請求 / 流量 / 峰值 / 異常` 這類技術物件，且句子裡有系統主語、引數、結果或邊界說明

### 回讀檢查

- 是否把「安慰」寫成了「替對方定義感受」
- 改完後是否還保留了基本溫度，而不是直接變成冷處理
- 是否把技術語境裡正常的「接住請求 / 接住流量」一起誤殺了

## 5.3 鄭重預告 / 身份認證式誇獎

### 識別訊號

- `我必須很認真地說一句`
- `我要講一個更深一點的東西`
- `這次我懂了，我真的懂了`
- `你問到了問題的核心`、`你的觀察力太敏銳了`
- 用 `頂刊作者 / 頂級研究者 / 真正高手` 這類身份標籤給對方「發證書」
- `我必須誠實地說 / 說句實話 / 坦白講`：誠實宣言變體，預告「我要講真話」來換可信度，和鄭重預告同一姿態
- `說個真實變化 / 缺點也說一句（免得你們說我恰飯）`：裝坦誠變體，用主動自曝換可信度，常見於公開推薦場景

### 預設動作

- 刪掉鄭重預告和認證式誇獎，直接說具體判斷
- 真的要誇時，只誇內容本身可見的優點，不把對方抬成某種身份
- 誠實宣言和裝坦誠只刪姿態層；自曝出來的缺點如果是真資訊（閃退頻率、適用邊界），內容必須保留
- 如果整段只是在認證「方向正確 / 進展很穩 / 不用擔心」，沒有任何可證實事實，就刪掉這層認證或明確說「現有資訊不足以判斷」；不要軟化成「方向沒問題 / 進展比較穩 / 不用太擔心」繼續替對方下結論

### 保留條件

- 該句本身是討論物件、梗圖樣本或反諷物件
- 使用者明確要保留誇張修辭、戲劇化語氣或表演式風格

### 回讀檢查

- 是否還在「預告我要說大實話」，而沒有先說內容
- 是否把具體判斷改成了空誇

## 6. 語域混搭

### 識別訊號

- 技術文裡突然出現小紅書腔、雞湯腔、商業黑話
- 公開文章裡突然插入過重的工程內部黑話
- 同一段裡正式通知腔和聊天腔來回切換
- 說明文、評測文裡強行套遊戲或職業框架比喻：把兩個日用品寫成「負責衝鋒陷陣的刺客」和「負責加血的奶媽」

### 預設動作

- 先判主語域
- 再刪異類語域詞，必要時統一主語和句長

### 保留條件

- 使用者明確要做反差風格
- 異類語域承擔引用、梗或明確修辭目的
- 中英混排裡的技術詞按技術語義判斷（`context 不崩`、`p99 突刺`），不因夾英文就當語域混搭

### 回讀檢查

- 改完後整段是否像同一個人在同一個場景裡寫出來的
- 是否因為過度統一而丟了必要的人味

## 7. 價值拔高骨架

### 識別訊號

- `這不僅僅是……更是……`
- `真正的 X 不是……而是……`
- `最後比拼的是……`
- `你看完會徹底開悟 / 看完就懂了 / 看完會震驚 / 看完不再 X`：承諾讀者讀完獲得頓悟、轉變或頓悟感，是另一種價值拔高 + 自媒體式承諾收尾
- 句子先給一個普通判斷，再硬抬成"更高層的洞見"

### 預設動作

- 先刪掉拔高層和骨架，只保留真正要說的判斷
- 如果剩下的話還是抽象，就改成更直接的事實句或評價句

### `in-place` 替代動作

- 不刪整句，先拆掉句內拔高骨架：`這不僅僅是 X，更是 Y` 可以改成 `這是 Y`，前提是 `Y` 本身有資訊量
- `真正的 X 不是 A，而是 B` 可以改成 `X 更看 B` 或 `B 更能影響 X`，不要靠二元對比製造洞見感
- `看完會徹底開悟 / 看完就懂了` 這類承諾式收尾，改成低承諾描述，例如 `下面只說我觀察到的幾個問題`
- 如果整句沒有可保留的資訊，保留原句並標註風險，不在 `in-place` 模式下自行刪掉

### 保留條件

- 對比兩邊都承載了新資訊，不是純姿態
- 作者就是在寫評論型公開表達，而且這一句確實在推進論證
- 單句正常對比可以保留；同一段連續疊加多組二元或拔高骨架，或骨架跨段分佈但全文密度超標時（閾值見 [結構反模式](./structures.md) 第 1 條），不要據此整段 `no-op`，應按 `in-place` 替代動作逐句降調，並保留兩邊的資訊與原有句數

### 回讀檢查

- 去掉骨架後，判斷是否更直接
- 是否把作者真正想強調的判斷也一起刪掉了
- 剝掉拔高層後，是否只剩「有改進 / 能提效 / 面臨挑戰」這類泛化空話；如果原文沒有更具體的資訊，允許變短並標註缺口徑，不要用新事實填空

## 8. 無源引用

### 識別訊號

- `研究表明`
- `資料顯示`
- `業內人士認為`
- `studies show`
- `experts say`
- 句子借權威開場，但沒有給研究名、機構、時間、連結或可核對來源

### 預設動作

- 先選模式，不要一上來就改句子：
  - `rewrite-safe`：刪掉權威鋪墊，只保留原文裡能獨立成立的判斷
  - `audit-only`：明確提示「缺來源 / 缺歸屬」，預設不替作者改成像已證實的說法
  - `rewrite-with-placeholder`：只在使用者明確要求保留原結構時，用「此處待補來源」這類佔位提醒保住結構
- `docs / status` 預設優先 `audit-only`
- `chat / public-writing` 預設優先 `rewrite-safe`
- 不要編造研究機構、年份、樣本量、行業共識或專家身份
- `audit-only` 只約束無源論斷本身；同一段還有二元骨架、商業黑話、表演性動作或空總結時，仍按各自規則清理，不能因為一處需要審計就把整段凍結成風險說明

### 保留條件

- 原文已經附了可核對來源，只是當前位置沒重複寫
- 這句話本身是在討論「無源引用」這種寫法，而不是在借它立論
- 使用者明確要做的是編輯批註，而不是直接改寫正文

### 回讀檢查

- 改完後，是否還在暗示「已有可靠研究支援」而其實沒有
- 是否為了保住句子氣勢，偷偷補進了原文沒有的事實
- 當前場景下，是否應該更保守地退回 `audit-only`
- 刪掉無源數字、預測或權威鋪墊後，是否只剩「更快 / 會改善 / 將改變行業」這類更泛的同向斷言；如果具體論斷無法獨立成立，`rewrite-safe` 應刪整條論斷，不要把它降格成空泛版本

## 9. Residual Audit / 二次審稿

### 識別訊號

- 第一遍已經把明顯套話清掉了，但還殘留一點「像被 AI 清理過」的味道
- 常見殘留固定只看 5 類：
  - 開場殘留：`結論先說 / 直接說結論 / 值得注意的是`
  - 總結殘留：`總的來說 / 最終來看 / 歸根結底`
  - narrator 殘留：`這也說明了 / 更重要的是 / 這意味著`
  - 空泛判斷殘留：`方向是對的 / 意義重大 / 真正理解了使用者`
  - 節奏過勻：連續幾句長度、抬手和落點都太整齊；或同一種句式骨架（尤其二元對比）反覆到能預判下一句形狀
- 快速定位手法：通讀一遍，圈出「換一個模型也能原樣寫出來」的段落。那幾段通常就是殘留最重的地方。先用這個問句圈範圍，再用上面 5 類對號入座，比逐條對錶快
- 這一步更像輕量拋光，不是再來一輪重寫

### 預設動作

- 先完成第一遍保真回讀，再決定要不要開第二遍；順序不要反
- 第二遍只做輕量修正：
  - 刪掉一個殘留開場或空總結
  - 把一句 narrator / 空泛判斷壓回直接句
  - 合併兩句過勻的事實句，或拆開一處過滿的句子
  - 同型句式骨架超出密度閾值時，只改超出的那幾處，換成中性連線或直接陳述
- `docs / status / code-context` 預設更保守：只有殘留真的明顯，而且不影響事實、術語和正式語體時才動
- 如果第二遍需要大改結構才能「更像人」，那通常說明該停在第一遍，而不是繼續拋

### 保留條件

- 提示層本身承擔標題、轉場或教學結構，不只是姿態
- narrator 句承載了必要的論證，而不是空解釋
- 句長整齊來自列表、步驟說明、狀態同步，不是 AI 拋光痕跡
- 句式骨架重複來自術語定義、並列條目或作者刻意承載論點的對比結構
- 第二遍一動就會讓 `docs / status / code-context` 變得更口語、失真或像宣傳稿

### 回讀檢查

- 第二遍後，文字是否更自然，而不是更「會寫」
- 是否只做了小修，不是把整段重寫了一遍
- 是否在不知不覺裡補了原文沒有的事實或態度
- `docs / status / code-context` 是否仍然保留原來的正式度和資訊密度

## 10. 動詞名詞化

### 識別訊號

- `進行了最佳化 / 實現了效率的提升 / 完成了對流程的梳理 / 起到了支撐作用 / 具有重要意義`
- `進行 / 實現 / 完成 / 開展 / 起到 / 具有` 後面跟一個動名詞，空動詞負責語法，實義全壓在名詞裡
- 英文對應 `perform an analysis of`、`conduct a review of`、`achieve an improvement in`
- 句子讀完能複述"做了什麼"，但複述出來比原句短一半

### 預設動作

- 還原成直接的動詞：`對流程進行了最佳化` → `把流程改順了`
- 還原後如果句子露出"其實沒說清誰做了什麼"，按「清理後的落點」合同處理，允許變短並標註缺口徑，不補事實

### `in-place` 替代動作

- 名詞化多數能句內還原，不需要刪句也不需要並句
- 還原後字數會掉，這是正常的：`實現了效率的顯著提升` → `快了不少`。`in-place` 的字數下限約束的是整句刪除，不約束句內還原
- 如果還原會丟掉原文聲稱的效果類型（`提升` 不能改成 `變化`），保留原謂詞方向再壓縮

### 保留條件

- 法律、合同、公文、正式公告裡的固定表述（`進行公示`、`予以受理`）
- `docs` 裡已經是穩定術語的名詞化（`增量編譯`、`執行計劃生成`）
- 使用者明確要求正式語體的對外材料

### 回讀檢查

- 改完後能不能一眼看出誰做了什麼
- 是否把專業術語裡本來就是名詞的概念也拆成了動詞

## 11. 同義詞躲避

### 識別訊號

- 同一個物件在相鄰 2–3 句裡換了 2 次以上說法，而且一次比一次抽象：`修表 → 這門手藝 → 這項技能`
- 英文同型：`parser → component → module`
- 代詞（`它 / 這個 / 該`）不算，正常照應本來就該用代詞

### 預設動作

- 統一回最具體的那個說法，其餘改成原詞或代詞
- 關鍵詞該重複就重複，不為"避免重複"付出精確度

### 保留條件

- 換的說法帶來新資訊或新限定（`修表 → 上門修表`）
- 兩個說法其實不指同一個物件
- 術語與口語的對照本身就是文字在做的事（`索引 / index`）
- 引用原文

### 回讀檢查

- 改完後指稱是不是更穩，讀者不用回頭確認"這三個詞是不是一回事"
- **反向自查**：這一輪清理 Tier 3 高密度詞時，自己有沒有用同義詞輪換降密度。有的話回退，改成刪掉多餘的幾次或換成具體資訊（見 [嚴重度分級](./severity.md) Tier 3）

## 12. 連詞過密

### 識別訊號

- `因為 / 所以 / 但是 / 同時 / 此外 / 然而 / 因此` 幾乎每兩句出現一個
- 連續三句每句都以連詞開頭，或同一個連詞在一段裡出現 3 次以上
- **只在 `public-writing` 的敘事、觀點、隨筆類文字上判**；`docs / status / code-context` 不判，理由和實測資料見 [結構反模式](./structures.md) 第 23 條

### 預設動作

- 刪掉一半，讀得斷的地方不補回來
- 刪完通讀一遍，事理接不上的地方再放回最必要的那個

### `in-place` 替代動作

- 連詞是句內成分，刪除不算刪句，`in-place` 下照常處理
- 刪到句子讀不通時改用中性銜接，不要為了減連詞把兩句併成一句

### 保留條件

- 連詞真的承擔轉折、讓步或因果，刪掉會讀錯
- `docs` 裡的條件說明和步驟銜接（`如果……則……`）
- 法律與規範文字；`status` 裡的時間線因果

### 回讀檢查

- 刪完之後事理還接得上嗎，有沒有出現需要讀者自己補邏輯的跳躍
- 是否在 `docs / status` 上誤用了這條

## 13. 裝飾性細節

### 識別訊號

- 沒有來源的精確時間、天氣、神態、房間擺設、菸酒食物和突然出現的對白
- `凌晨三點`、`第三根菸`、`桌上的咖啡早就涼了`、`窗外下著雨`
- 判據是兩條同時成立：細節沒有來源（不是使用者提供的、不可核驗），並且刪掉後文的事實、判斷、因果都不變
- 和 §5.2 的假口語化不同：那個是硬塞網路流行語，這個是偽造生活細節。假細節越具體，AI 味越重

### 預設動作

- 刪掉。刪完段落如果沒了落點，用原文已有的資訊重組，不補新細節

### `in-place` 替代動作

- 裝飾細節常常佔滿整句，`in-place` 下不刪句，保留原句並標註 `[無來源細節，建議人工確認是否刪除]`
- 細節只是句內修飾成分時（`他盯著那行報錯，窗外下著雨`），可以句內刪掉修飾，保留主幹
- `bounded` 下整句裝飾細節進「建議刪除（待確認）」清單，理由寫"無來源且刪後資訊不變"

### 保留條件

- 使用者自己提供的經歷細節，哪怕瑣碎也保留
- 細節確實改變後文（`那天是週日，維修點沒開門`）
- 虛構、小說、劇本裡屬於人物視角和行動的細節
- `docs` 裡的復現條件、環境說明、時間戳和日誌片段

### 回讀檢查

- 刪掉的細節裡有沒有其實承擔了因果的
- 有沒有把使用者自己講的經歷當成模型編的細節刪掉——這是本節最危險的誤殺方向

## 14. 借喻場混用

### 識別訊號

- 同一段裡從多套不相干的比喻系統藉詞：道路競賽、戰爭攻防、建築災害、溫度、倉儲、海洋航行、機器器官
- `賽道的護城河正在坍塌，需要重新點燃引擎，才能在這波浪潮裡活下來`
- 短距離內（約 800 字）命中 3 套以上才算命中；單套用得準不處理

### 預設動作

- 先全部還原成本義
- 還原後意思已經清楚的，一個比喻也不用放回，不要換一套新比喻替代

### `in-place` 替代動作

- 借喻詞多數是句內詞，替換成本義不涉及刪句
- 還原後如果原句只剩空話，說明這句話本來就只有比喻沒有資訊，保留原句並標註，不擅自補事實

### 保留條件

- 所寫物件本身就是這些東西（真的在講倉庫、溫度、船）
- 行業穩定術語：金融的 `槓桿`、投資語境的 `護城河`、技術語境的 `搜尋引擎 / 程式碼倉庫 / 商品庫存`
- 使用者明確要求的修辭風格
- 小說、詩歌和抒情寫作按意象是否屬於同一套感受判斷，不按數量機械刪

### 回讀檢查

- 還原成本義之後，讀者是不是更清楚在說什麼
- 有沒有把字面用法（`程式碼倉庫`、`搜尋引擎`）當借喻改掉

## 15. 量化表述有歧義

### 識別訊號

- 原文的數量關係本身有多種解釋：`縮小了 3 倍`、`翻了 1 倍`、`不超過 100 以上`、`預計大約在 3 點左右`
- 百分比只給起止值，卻需要進一步判斷說的是百分點變化還是相對增幅
- 句子看起來像病句，但改順之前必須先替作者選擇一種數量關係

### 預設動作

- 改寫側預設不替原文修正量化邏輯，不把 `縮小了 3 倍` 擅自改成 `縮小到原來的 1/3`
- `annotation mode` 標成歧義點；`docs / status` 按 `audit-only` 標註待確認
- `chat / public-writing` 裡，如果這段量化說法不承擔關鍵資訊，可以壓縮掉整個量化說法；如果承擔關鍵資訊，就保留原表述並提示確認。兩種情況都不能換成新的數量關係
- 任何情況下不得自行補充原文沒有的基數、年份、期限或測量結果

### `in-place` 替代動作

- 只在刪掉量化短語後句子仍完整、且該數量不承擔關鍵資訊時做句內壓縮，例如刪掉倍數後保留原文已有的變化方向
- 其餘情況保留原句並標註 `[量化關係有歧義，待確認]`，不在句內猜一個「更正確」的數值或比例

### 保留條件

- 百分點與相對增幅已經寫清：`從 20% 升到 30%，提高 10 個百分點，相對增幅 50%`
- 基數、單位、起止值和測量口徑完整，數量關係沒有歧義
- 引用、日誌、報錯、合同原文或使用者明確要求逐字保留的量化表述；需要提醒時在原文外標註，不改引用內部

### 回讀檢查

- 改寫後是否出現了原文沒有的分母、基數、年份、期限、測量值或推導結果
- 是否把一種有歧義的說法偷偷固定成了某一種解釋
- 正常的百分點、百分比、單位和基數是否被誤判後改動
