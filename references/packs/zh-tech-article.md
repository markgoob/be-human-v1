# Scene pack — 技術文章 / 教學 / 部落格（ZH）

適用：工程部落格、踩坑紀錄、架構說明、教學文、實測報告。

信心標記：〔繼承〕= 沿用母技能已驗證的規則；〔推論〕= 跨語言合理延伸，中文側沒有量測基線；〔臆測〕= 憑寫作經驗判斷，讀者可以推翻。本檔案沒有任何中文語料的統計數字，因為不存在。

---

## 1 骨架〔繼承〕

原封不動沿用，只是換一個語言執行。

1. **問題先於題目。** 第一段寫逼出這個問題的具體情境：哪個服務、哪個數字、哪天壞掉。沒有真實情境就不要編一個 —— 誠實的體裁是「X 的筆記」，不是事故現場。
2. **至少一個立場，而且說清楚什麼時候不適用。** 立場要寫成自己的判斷，並附上會讓你改變主意的條件（例如「如果你的寫入低於 1k/s，這整套都不用做」）。
3. **深度照興趣分配，不照對稱。** 讓你意外的那一節可以是安裝步驟的五倍長；不要每個替代方案各給一段、誰都不給結論。
4. **失敗路徑要留著。** 第一版怎麼寫、為什麼不行、下次會跳過什麼 —— 沒走通的那條路才是有資訊量的部分，也是讀者判斷「這是人寫的」的地方。
5. **數字一定帶條件。** 機器規格、版本、資料集大小、跑幾次。條件補不出來就不要印那個數字。
6. **QUD 檢查。** 如果小標的問題序列是「什麼是 X → 為什麼 X 重要 → 怎麼做 X → 結語」，那是題目綱要不是文章，照實際發生的順序重排。
7. **語態：第一人稱、口語縮寫、允許離題一兩句。**

## 2 中文技術寫作的 AI 徵候〔推論〕

中文 AI 文本會把內容農場與社群平台的體裁灌進技術寫作。以下每一列都是跨語言延伸，沒有量測支撐。

| 徵候 | 訊號（可搜） | 預設動作 | 保留條件 |
|---|---|---|---|
| 誇張開場 | 「在當今這個…的時代」「隨著…的快速發展」「重要性不言而喻」「眾所周知」 | 整句刪，第一段直接寫事故或數字 | 無。這類句子沒有任何一種文體需要它 |
| 內容農場標題語 | 「一文看懂」「一文搞懂」「保姆級」「手把手」「全網最全」「乾貨滿滿」「必看」「收藏」 | 換成描述性標題：〈把 p99 從 1.4s 降到 420ms 的三次嘗試〉 | 若刊登平台的既有標題就長這樣（例如公司行銷部門指定），保留標題但正文不得沿用該語域 |
| 情緒化小標 | 「震驚！」「這一步，決定了成敗」「沒想到吧」「翻車現場」 | 小標改寫成該節真正做了什麼，含結果：「第一版：TTL 加隨機抖動（沒用）」 | 若整篇是刻意的幽默體且從頭到尾一致，保留但降到一兩處 |
| 自問自答 | 「那麼問題來了」「為什麼會…呢？」「答案是」「你可能會問」 | 刪掉問句，直接寫答案那一句 | 真的要提出讀者會有的反對意見時保留一次，而且後面要真的回答那個反對，不是自己餵球 |
| 空的展望收尾 | 「未來還有很長的路要走」「值得我們持續關注」「相信在不久的將來」「歡迎交流討論」 | 整段刪。結尾停在建議，或停在你真的還沒解的問題 | 若有具體的下一步（下一篇要測什麼、issue 編號），保留但寫成具體項目 |
| 兩面俱到的結語 | 「各有優缺點」「需要根據實際情況權衡」「沒有銀彈」 | 給出你會選哪個，以及選擇的門檻值 | 若真的量測後無顯著差異，就寫「差異在誤差範圍內」並附上量測條件 |
| 段首連號 | 每段開頭「首先」「其次」「再者」「最後」 | 要嘛做成真的清單或表格，要嘛改成有論證的散文 | 步驟教學的操作段落可以編號，但那要是真的清單，不是散文裝清單 |
| 中文學術填充 | 「值得注意的是」「不難發現」「由此可見」「綜上所述」「總而言之」 | 刪 | 前面數節彼此獨立、讀者需要一句合流時保留一句，且該句必須帶新資訊（推薦哪個），不能只複述 |
| 對仗排比小標 | 三個小標字數一致、句式一致（「認識 X／理解 Y／掌握 Z」） | 打散。真實文章的小標長短不一 | 若是真的三個平行步驟 |
| 導覽句 | 「本文將帶你…」「接下來我們一起看看」「話不多說，直接開始」 | 刪 | 無 |
| 憑空造詞 | 中途自創概念標籤並加引號（「快取雪崩效應症候群」） | 用白話描述，或用業界既有名詞 | 業界既有名詞（快取雪崩、驚群效應）不算造詞 |
| emoji 小標 | 小標前面掛 🚀 🔥 ✅ | 拿掉 | 若該部落格全站一致如此 |

### 改寫示例

開場：

- ✗「在當今這個資料量爆炸的時代，快取策略的重要性不言而喻。本文將帶你一文看懂 Redis 的三種快取模式。」
- ✓「結帳 API 的 p99 從 80ms 跳到 1.4s。查下去是一批 key 每天凌晨同時過期，全部打到資料庫。以下是我們換掉 TTL 策略的過程，還有第一版為什麼失敗。」

自問自答：

- ✗「那麼問題來了，為什麼會發生快取雪崩呢？答案是大量 key 在同一時間過期。」
- ✓「大量 key 在同一時間過期，就會一起打到資料庫。」

收尾：

- ✗「快取這條路還很長，未來我們會持續探索更好的方案，也歡迎大家一起交流。」
- ✓「還沒解的是冷啟動那三十秒，目前靠預熱腳本蓋過去。如果你的寫入低於 1k/s，這整套都不用做。」

數字：

- ✗「換成新方案後效能提升了三倍。」
- ✓「p99 從 1.4s 降到 420ms。單台 c6i.2xlarge、PostgreSQL 15.4、資料集 2,400 萬列、跑五次取中位數。」

## 3 支語陷阱〔推論〕

技術文章是支語密度最高的中文體裁，因為作者多半在讀簡體技術文。Layer 1 已經處理通用詞，這裡只列本體裁高頻的。

| 支語 | 臺灣用法 | 備註 |
|---|---|---|
| 對齊（指取得共識、同步進度） | 同步、取得共識 | 「對齊」指文字排版或記憶體 alignment 時是正確的，保留 |
| 落地 | 實作、上線、導入 | 「這個方案落地了」→「這個方案上線了」 |
| 顆粒度 | 細緻程度、粒度 | 若沿用學術文獻的「粒度」可保留；「顆粒度」不要 |
| 復用 | 重複使用、再利用 | 程式碼再利用 |
| 健壯 | 穩健、耐操 | robustness → 穩健性 |
| 冗餘（指多寫、贅） | 多餘、重複、贅 | **但 redundancy 意義下的「冗餘」在臺灣是正確用語**：冗餘電源、冗餘備援、RAID 的冗餘磁碟。判斷依據是它指「刻意保留的備份」還是「不必要的重複」 |
| 調用 | 呼叫 | API 呼叫 |
| 報錯 | 錯誤訊息、出錯、拋出例外 | 臺灣工程師口語確實會說「它報錯了」，聊天與 review 留言可接受；**對外技術文章、教學、正式文件一律改掉**，因為讀者會把它當作簡體來源的痕跡 |
| 兜底 | 保底、後備、fallback | 直接用 fallback 也可以 |
| 埋點 | 事件追蹤、打點 | |
| 提測、聯調 | 送測、整合測試 | |
| 質量 | 品質 | |
| 內存 | 記憶體 | |
| 緩存 | 快取 | |
| 隊列 | 佇列 | |
| 並發 | 並行、並發 | 臺灣兩者都見得到，同一篇內一致即可 |

保留英文不譯的詞（臺灣工程圈的既定語域，硬翻反而更像外來文）：nit、blocking、LGTM、edge case、refactor、race condition、breaking change、rollback、deprecate、fallback、trade-off。

## 4 中文密度與虛詞〔推論〕

中文以字元計。中文虛詞會讓字元數虛胖：字數多不等於資訊密度高，刪虛詞會同時降低字數並提高密度，所以中文段落的密度判斷要在刪完虛詞之後才做。

固定可刪的膨脹句式：

- 「進行 + 動詞」→ 動詞。進行測試 → 測試；進行最佳化 → 最佳化。
- 「透過…的方式」→ 用。
- 「…的相關」→ 刪「相關」。
- 「在…方面」「就…而言」→ 多半整片可刪。
- 「具有…的特性」→ 直接寫那個特性。
- 「能夠」→ 能；「進行了一次」→ 做了。
- 「是一個…的工具」→ 直接寫它做什麼。

程式碼、路徑、版本號各算一個單位，不要因為 `docker compose up -d` 很長就以為那段很密。〔繼承〕

## 5 排版〔推論〕

- 中文散文用全形標點；行內程式碼、指令、路徑、版本號用半形，且不要在半形內容外面加全形括號以外的修飾。
- 引號用「」，巢狀用『』。不要用 “ ” 或 " "。
- 中英之間加不加半形空格都可以（臺灣兩派都有），**但整篇必須一致**。混用是最明顯的機器痕跡。
- 數字與單位之間不加空格：1.4s、420ms、8GB。百分比同理。
- 不要用全形括號包住純英文詞：〈…（cache stampede）〉→〈…(cache stampede)〉或直接寫「快取驚群」。

## 6 與 scope 的互動

- 整段的空展望收尾、導覽句、誇張開場多半是**整句／整段刪除**。在 bounded scope 下這類刪除進待確認清單，不要自己動手；在 in-place scope 下只標記不刪。
- 「補上量測條件」不是插入事實，是向使用者索取事實：條件問不到就刪掉那個數字，不要自己生一組機器規格。這條沒有例外。

## 7 重讀檢查

念完初稿問這七題，任何一題答不出來就回去改：

1. 第一段有沒有一個具體的時間、數字或錯誤？
2. 全文有沒有一句話是讀者可以不同意的？那句話有沒有附上不適用條件？
3. 有沒有一段在寫「這條路走不通」？
4. 每個數字後面有沒有機器、版本、資料量、次數？
5. 小標念下來像不像目錄（什麼是／為什麼／怎麼做／結語）？
6. 搜尋這幾個字串是否為零命中：「那麼問題來了」「值得注意的是」「綜上所述」「一文」「不言而喻」「隨著」「未來還有很長」。
7. 搜尋支語表左欄是否為零命中（「冗餘」需人工判斷是備援義還是贅義）。
