# Protected Spans

> 本檔案是解釋、示例與操作細則；行為合同的單源是 `SKILL.md`，兩處表述不一致時以 `SKILL.md` 為準。

> 在追求「更像人」之前，先把不能漂的片段保護住。

這份文件把 `SKILL.md` 裡的 no-touch 原則展開成一個可執行的預檢清單。  
`v1.7.0` 先採用 prompt 內 checklist，不要求額外輸出 `facts ledger` 格式。

使用順序：

1. 判場景
2. 先掃一遍 protected spans
3. 再做刪句、並句、換主語、降調
4. 回讀時逐類核對 protected spans 是否還在

**信心標記**：§1.1–§1.5 是原規格既有條目，沿用不另標。新增條目（§1.6、§1.7、§6，以及各節內的中文細則）逐條標 `grounded` / `inference` / `speculative`。兩個母技能都沒有中文量測基線，因此任何跨語言延伸一律是 `inference`。

## 1. Protect first

先保護，再改寫。預設要先劃出來的內容有：

### 1.1 Numbers, dates, ranges, units

- 數字
- 百分比
- 時間
- 日期
- 版本號
- 區間
- 時間範圍與時間跨度（如「未來十年」「over the next decade」「三個月內」）
- 單位

預設規則：

- 不改數值
- 不隨手四捨五入
- 不把精確說法改成模糊說法
- 不放大、縮小或模糊化時間跨度
- 不補原文沒有的比較項
- 刪除整句時按無源引用規則處理；如果保留相關論斷，不得把原時間跨度改成另一個跨度

### 1.2 Names and attribution

- 人名
- 組織名
- 產品名
- 模組名
- 服務名
- issue / PR / RFC 編號
- 責任主體和觀點歸屬

預設規則：

- 不換主體
- 不模糊「誰做的 / 誰說的 / 誰負責」
- 不把原來的判斷改成像是別人已經證明過

### 1.3 Quoted text and titles

- 引號內原文
- 引用規範
- 文章標題
- 報告名
- 原話裡的關鍵詞

預設規則：

- 引號內容預設原樣保留
- 只在使用者明確要求時改引號內正文
- 不把引用改寫成概述後再塞回引號

### 1.4 Commands, code, params, fields, paths

- 指令
- 程式碼區塊
- 介面名
- 參數名
- 欄位名
- 設定項
- 檔案路徑
- 環境變數

預設規則：

- 拼寫、大小寫、符號、底線、連字元都保留
- 不翻譯程式碼語義
- 不把註解外的技術片段改成人話

### 1.5 Errors, logs, statuses, metrics

- 錯誤訊息
- 日誌原文
- HTTP 狀態碼
- 指標名
- 實驗結果
- 監控數值
- 結論裡的度量關係

預設規則：

- 不換錯誤類型
- 不丟時間範圍、樣本範圍、比較基線
- 不把「觀察到」改成「已經證明」

### 1.6 對白、引語與世界內文件

〔grounded：對白與 in-world 文件不可規整，是母技能明文規則。套到中文的細則另標。〕

範圍：

- 角色說出口的話（引號內、破折號引導、劇本體台詞）
- 直述的內心獨白
- 世界內文件：公告、備忘錄、公文、書信、日記、簡訊、聊天記錄、系統提示、告示、廣告詞
- 轉述他人的直接引語（含 §1.3 的引號原文，此處是它在虛構與擬真文本裡的延伸）

核心判斷：對白與世界內文件是「被寫出來的物件」，不是敘述者的散文。它們的語病、囉嗦、公式化、語域錯位，多半是刻畫手段，不是缺陷。

- **signal**：一段文字讀起來「不夠好」，但它位在引號內、書信／公告區塊內，或明確標示為某個人寫的段落內。
- **default action**：整段標為 protected。它不是候選，不消耗風格預算裡的任何一個 move。
- **retention condition**：怪癖在同一位說話者、同一份文件內部一致，就留。前後不一致（同一角色時而口語時而書面）才回報，而且是回報，不是靜默拉平。
- **reread check**：把敘述層和對白層拆開各讀一遍。同一個怪癖如果在敘述層也出現，那多半是 AI 腔，不是人物聲音——這時該改的是敘述層。

具體不做的事：

- 不修角色的病句、贅字、口頭禪、跳針、重複
- 不把方言、行話、粗話、外語夾雜改成標準書面語
- 不把刻意僵硬的公文體、法律體、客服體改順
- 不因為某個詞在禁用清單上就從角色嘴裡拿掉。禁用清單管敘述層與 AI 腔，不管人物語言。
- 不把台詞的破碎標點補齊：省略號、破折號、沒有句號的中斷句都是節奏
- 不統一不同角色的句長與節奏——那正是角色之間的辨識度

中文細則：

- 用語層（Layer 1）在敘述層無條件生效；在對白與世界內文件裡，地域用語屬於刻畫。一個中國角色說「視頻」「軟件」是正確的塑造，不是錯字。做法：不靜默轉換，標一次、問一次，使用者確認後才統一處理。〔inference〕
- 標點同理。世界內文件若在模仿某種真實文體（電報、終端輸出、舊式公文、手機訊息），它的半形／全形混用、缺標點、全大寫都屬於物件本身的樣貌。〔inference〕
- 敘述層的中文標點規範照舊：全形標點、「」引號。規範管的是敘述層與引號外的說明文字。〔inference〕

例：

> 老陳把單子推回來：「這個、這個不行啦，你那個什麼系統，我們這邊沒有在用那個的。」

保護：整句對白，含「這個、這個」的重複與「有在用」的臺灣口語。  
可改：引號外的敘述。若敘述層寫成「老陳表達了對系統相容性的疑慮」，那是 AI 腔，該改的是這句。

### 1.7 作者本人的已驗證語癖

〔grounded：保護作者既有語癖是母技能明文規則。驗證程序與門檻另標。〕

目標是改成**這位作者的聲音**，不是改成一種通用的「人味」。一個被抹平到誰都可以寫的成品，即使沒有一條 AI tell，也是失敗品。

範圍舉例：

- 慣用連接詞與轉折方式
- 偏好的句長與段長
- 固定開場、固定收尾、簽名式結語
- 括號裡自嘲、括號裡補充的習慣
- 特定標點癖好（愛用分號、愛用破折號、幾乎不用驚嘆號）
- 個人固定的術語譯法與大小寫寫法
- 刻意的不對稱：例如永遠只列三點、永遠不寫結論段

**驗證程序（venue-corpus sampling）**——沒跑完這四步，就不算語癖：

1. **取樣**：抓同一發表場域裡作者先前的成品。同一個 repo 的 commit message 與 PR 描述、同一個部落格、同一個 issue tracker、同一本書已完成的章節。〔inference〕
2. **重現**：同一特徵要在至少 2–3 份不同的先前成品裡自然出現。這個門檻是操作性約定，不是量測結果，沒有語料證據支持特定數字。〔inference〕
3. **來源乾淨**：取樣優先取沒有經過助手產出的文本。若前作本身可能是 AI 寫的，那個特徵不能拿來當作者語癖用，否則會把上一輪的 AI 腔洗成「風格」。〔inference〕
4. **場域對齊**：語癖跟場域綁定。作者在 issue 回覆裡的隨性語癖，不能自動搬到 README 或對外公告。〔inference〕

沒通過驗證的特徵不是語癖，是普通候選，照常規流程判斷。**不得以「這大概是作者風格」為由保留**。

- **signal**：某個特徵在候選清單上，但你在作者前作裡也見過它。
- **default action**：先跑驗證程序，再決定。通過就標 protected 並記為該場域的語癖。
- **retention condition**：通過四步驗證，且該特徵不牴觸 Layer 1 的用語與標點對錯。
- **reread check**：把成品和取樣的前作並排讀。若成品明顯比前作更乾淨、更整齊、更沒有個人痕跡，就是改過頭了。

衝突處理：

- 語癖 vs Layer 1 用語／標點 → 對錯優先，語癖讓路。用語與標點是對錯問題，不是風格問題。作者若明文要求保留（例如堅持某種括號寫法），記成使用者指定的例外，而且只在該場域生效。〔inference〕
- 語癖 vs AI tell 清單 → 通過四步驗證的語癖優先，保留。
- 語癖 vs 密度預算 → 語癖不佔預算，因為它本來就不是我們要動的東西。
- 語癖 vs 專案風格指南、團隊固定說法 → 對外文件以風格指南為準，除非作者本人就是規範的擁有者。〔inference〕
- **無法取樣**（新使用者、沒有前作、拿不到場域語料）→ 不主張語癖。發現疑似特徵就在報告裡問一句，不要靜默保留，也不要靜默刪掉。〔inference〕

## 2. What may change around them

protected spans 外面的這些內容通常可以改：

- 開場套話
- 總結式收尾
- 商業黑話
- narrator 腔
- 姿態層
- 空洞判斷包裝

可以做的動作：

- 刪掉 span 前後的廢話
- 調整句序，但不改變事實關係
- 把抽象結論壓回具體動作
- 合併重複句，但不要吞掉保護項

如果一句話只有靠改 protected span 才能變自然，優先保真，寧可保留一點生硬。

## 3. Scene notes

### `status`

重點保護：

- 時間線
- 當前判斷
- 下一步
- 風險歸屬
- 指標和範圍

不要為了更順，把「風險」「阻塞」「未確認」改輕。

### `docs`

重點保護：

- 術語
- 條件
- 順序
- 指令
- 設定
- 系統主語

不要為了口語化犧牲可檢索性。

### `code-context`

重點保護：

- 程式碼本體
- 註解裡描述的真實行為
- 參數
- 回傳值
- 約束條件

可以改註解的 AI 腔，但不能把函式行為改錯。

### `fiction`

〔inference：本節把母技能的虛構規則整理成保護清單，中文部分無量測基線。〕

重點保護：

- 對白與世界內文件（§1.6），整段
- 敘述者既定的人稱、時態感、語氣
- 已建立的意象、命名、in-world 專有名詞（世界內術語就是術語，比照 §1.4 的技術術語）
- 時序切換點與視角切換點

可改的是敘述層的 AI 腔：解釋過度、情緒總結、每段結尾的意義升華、把已經演出來的東西再說一次。

判斷順序：先確定這句是敘述還是有人在說話或有人在寫；判錯層，後面全錯。

### `mixed`

重點保護：

- 引用邊界
- 局部場景切換點
- 引號、程式碼區塊、檢討區塊、公告區塊裡的原有格式

先判哪裡是正文，哪裡是引用或嵌入塊，再決定哪些區域能動。

## 4. Worked examples

### A. `status`

原文：

> 昨天把連線池上限從 20 調到 100，504 先壓下來了。後面再觀察 24 小時，如果錯誤率還在 0.1% 以下就全面上線。

保護項：

- `20`
- `100`
- `504`
- `24 小時`
- `0.1%`

可改部分：

- `先壓下來了`
- `後面再觀察`

### B. `docs`

原文：

> 執行 `bin/migrate --tenant=prod` 後，如果日誌出現 `schema mismatch`，先檢查 `DB_SCHEMA_VERSION` 是否和線上一致。

保護項：

- `bin/migrate --tenant=prod`
- `schema mismatch`
- `DB_SCHEMA_VERSION`

可改部分：

- `先檢查`
- 前後解釋層

### C. `mixed`

原文：

> 使用者說「別改我這句，原樣保留」。正文裡只要把「值得注意的是」這類套話清掉就行。

保護項：

- `「別改我這句，原樣保留」`

可改部分：

- 引號外的正文說明

### D. `fiction`（對白）

原文：

> 「不是，你聽我講——那個板子昨天就沒有在跑了，我跟你講三次了。」阿凱把筆電轉過來，螢幕上什麼都沒有。這一刻，他意識到兩人之間的溝通鴻溝有多深。

保護項：

- 整句對白，含中斷破折號、「沒有在跑」的臺灣口語、重複語氣
- `阿凱`

可改部分：

- `這一刻，他意識到兩人之間的溝通鴻溝有多深。`——敘述層的意義升華，前一句已經演完了，直接刪

不可做：

- 把對白改成「這塊板子昨天就已經停止運作，我已經告知你三次。」——這是把角色改成公告
- 因為「跑」不夠精確就換成「執行」

### E. 作者語癖

取樣：作者前六篇 release note，其中四篇以「這版比較無聊：」開頭，且每篇都在某個括號裡放一句自嘲。

判定：通過驗證（同場域、≥2–3 份、非助手產出）→ 開場句型與括號自嘲是語癖，保護，不列入候選。

同一篇裡若只出現過一次、前作找不到 → 不算語癖，照常規流程判斷。

可改部分：其他段落的套話、每段結尾的總結句。

## 5. Final check

回讀時至少核對這 7 件事：

1. 數字、日期、單位、版本號有沒有漂
2. 主體、歸屬、責任關係有沒有被換掉
3. 引號、程式碼、指令、路徑、參數有沒有被改壞
4. 錯誤、狀態碼、指標和比較關係有沒有被寫鬆
5. 有沒有為了「更像人」補進原文沒有的事實、來源或判斷
6. 對白與世界內文件有沒有被「改順」：語病補掉了、方言拉平了、標點補齊了、角色之間開始講同一種話
7. 作者的已驗證語癖有沒有被抹平成通用人味；成品和前作並排讀，是不是變得更沒有個人痕跡

看不準時，優先保留 protected span，不要賭。

## 6. 跨語言邊界（cross-reference）

以下片段在中文段落與英文段落裡同樣受保護，跟 matrix language 無關：

- inline code 與程式碼區塊
- 版本字串（`v1.7.0`、`2.3.1-rc2`、`Python 3.11`）
- 錯誤訊息與日誌原文
- 檔案路徑與 URL
- 識別符：函式名、變數名、旗標、環境變數、欄位名、型別名
- JSON / YAML / TOML 與其他設定片段

共同規則：

- **這些片段內部的標點永遠不轉全形。** 半形逗號、句點、引號、括號、冒號、空格一律照原樣。中文段落的全形標點規範只作用在 protected span 外面。
- 中文句子裡的英文術語是術語，不是英文候選；英文句子裡引用的中文原文是引文，不是中文候選。
- 邊界怎麼切、matrix language 怎麼判、夾雜片段歸哪一層，看 `references/language-routing.md`，此處不重述。
