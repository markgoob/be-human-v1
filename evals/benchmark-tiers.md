# Benchmark 分層與發布門檻

> 本機安裝未收錄 `run-eval.md` 與 `benchmark.md`（評測基建，非 skill 規則）。下列連結指向上游 repo。

> 2026-07-23 起生效。本檔案是評測用例分層和發布門檻的單源：判分列定義見 [run-eval.md](https://github.com/MrGeDiao/shuorenhua/blob/main/evals/run-eval.md)「判分分層」，逐條預期仍在 [benchmark.md](https://github.com/MrGeDiao/shuorenhua/blob/main/evals/benchmark.md)。
> 防放水約束：分層判據先於跑分定稿；任何用例的層級變更都要在下面的例外表補一行理由並記入 CHANGELOG，不得在一輪實跑結果出來後為達標移動層級。

## 為什麼分層

舊門檻把事實保真、scope 合同、明顯套路、主觀風格和輸出協議混進同一個 `SF > 90%` 分母，並要求所有模型統一達標。後果是：主觀風格上的合理模型分歧被當成規則缺陷修，規則圍著單個失敗用例長例外（v2.1.0 檢討結論）。分層之後，失敗的嚴重性決定它的後果：硬約束失敗阻塞發布，風格失敗進趨勢報告。

## 層級定義

| 層級 | 含義 | 進門檻嗎 |
|------|------|----------|
| L0 輸出協議 | 標題、判定鏈、區間完整性等 harness 格式 | 否；格式壞的輪次修復後重跑或由執行者歸一化，在 results 裡記錄，不零化內容分 |
| L1 硬約束 | protected spans 漂移（含 code-context 裡的真實執行行為、適用條件和邊界）、編造事實/來源/資料、scope 越界（in-place 刪句/並句/重排，bounded 並句或刪除清單混實句）、責任主體或歸屬改變、無源數字/時間跨度降格、引用與使用者指令邊界破壞 | 是；任何用例出現即硬失敗 |
| L2 風格目標 | 明顯套路的清除：諂媚開場、空總結、商業黑話、姿態層、語域混搭等 | 報告 + 趨勢；不設跨模型統一線 |
| L3 風格觀察 | 兩位合格編輯可能對預期輸出合理分歧的用例 | 否；按可接受集判，只記錄 |

## 歸屬規則

- 全部 SNF：誤殺結果記在 judge 第二列並單獨統計；普通誤殺不記 L1，其中涉及編造或受保護片段破壞的誤殺才同時按 L1 硬失敗處理。
- 全部 SF：硬約束子項一律按 L1 判（judge 硬約束列）；風格預期預設 L2，例外見下表。

## 例外與特記

| 用例 | 判定 | 理由 |
|------|------|------|
| SF-15 | 風格列 L3 | "長短句交替、製造呼吸感"是節奏偏好，兩位合格編輯可以合理給出不同答案；硬子項（不編造指標）照常 L1。 |
| SF-40 | 風格列 L3 | 三組骨架分佈在三個段落，操作手冊只約束"同段連續疊加"；樣本內容本身是作者刻意用對比結構論證"反對過度整理"，no-op 有合理性。硬子項照常：留存 ≥ 0.85、不刪句、不併句、不重排。 |
| SF-42 | 風格列 L3 | 與 scene-packs"README intro 允許一句有辨識度的定位句"存在真實張力，定位句 vs 空誇是編輯判斷；硬子項（不得編造能力承諾）照常 L1。 |
| SF-36 | L2，標準寫死 | 透過 = 輸出不再含方向/風險認證（刪除或標註"資訊不足以判斷"均可）；降格成 `方向沒問題 / 不用太擔心` 記 ❌。 |
| SF-18 | L2 | 2026-07-23 修復 audit-only 凍結許可衝突（run-eval / rewrite prompt 與操作手冊矛盾）後生效；此前失敗的主因是合同矛盾，不是模型能力。 |
| SF-05 | L2，預期已改寫 | 2026-07-23 起預期對齊 rewrite-safe 合同（依賴無源引用的論斷整條刪除）；歷史輪次分數不可比。 |
| SF-09 / SF-12 | L2，殘留寬容 | 主病灶（被動堆砌 / 小紅書腔）清除可判定；殘留單個次要詞條記 ⚠️，不記 ❌。 |
| SF-19 / SF-41 | 硬約束為主 | 用例核心即引用邊界 / bounded 刪除清單紀律，屬 L1；風格列只判殘餘姿態層。 |

## 發布門檻（2026-07-23 起）

1. L1 硬約束失敗 = 0（含 SNF 中涉編造 / 受保護片段破壞的誤殺）。
2. SNF 誤殺率 < 10%。
3. 本版新增或修訂用例的 targeted 雙模型達標。
4. L2 風格透過率按模型分別報告，並與上一版對比；明顯回退（> 5 個百分點）需要在 results 裡給出解釋。L3 只記錄，不進任何門檻。

同時繼續並列報告舊口徑 SF 透過率，保持歷史可比；舊口徑不再作為發布判斷依據。

## 維護

- [benchmark.md](https://github.com/MrGeDiao/shuorenhua/blob/main/evals/benchmark.md) 用例增刪後，檢查本檔案的例外表是否需要同步。
- 新用例預設落 L2；要進 L3 必須滿足"兩位合格編輯可能合理分歧"的判據，並在例外表寫明理由。
- 想把某條從 L2 降到 L3 時，先問：失敗是因為規則說不清，還是因為答案本來就不唯一？前者修規則，後者才降層。
